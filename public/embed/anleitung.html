Embed-Widgets – Anleitung & Live-Demo

Mit zwei Zeilen HTML zeigst du Immobilien, Bauprojekte und Wohneinheiten aus dem Immo Manager auf jeder Webseite – ohne WordPress, ohne Plugin, ohne Programmierung. Die Beispiele auf dieser Seite sind echte Widgets, die live aus dieser Installation laden.

So funktioniert es

  1. Ein kleines JavaScript (immo-embed.js, ca. 40 KB, keine Abhängigkeiten) wird einmal pro Seite eingebunden.
  2. Überall, wo Inhalte erscheinen sollen, steht ein Platzhalter-Element <div data-immo-embed="…">.
  3. Das Script lädt die Daten über die öffentliche REST-API dieser Installation und rendert sie isoliert in einem Shadow DOM. Das CSS der Zielseite kann nichts kaputt machen – und umgekehrt.
  4. Änderungen im Immo Manager (neue Immobilie, Status „verkauft", Preis) erscheinen sofort auf allen eingebundenen Seiten.

Schnellstart (2 Schritte)

1. Script einbinden – einmal pro Seite, am besten vor </body>

<script src="SCRIPT_URL" defer></script>

2. Platzhalter dort einfügen, wo das Widget erscheinen soll

<!-- Bauprojekte als Grid -->
<div data-immo-embed="projects" data-columns="3" data-title="Unsere Bauprojekte"></div>

<!-- Wohneinheiten eines Bauprojekts (ID oder Slug) -->
<div data-immo-embed="units" data-project="mein-bauprojekt"></div>

<!-- Immobilien-Grid mit Filterleiste und „Mehr laden" -->
<div data-immo-embed="properties" data-mode="sale" data-limit="6" data-filters="1"></div>

<!-- Einzelne Immobilie / einzelnes Bauprojekt -->
<div data-immo-embed="property" data-slug="meine-immobilie"></div>
<div data-immo-embed="project" data-slug="mein-bauprojekt"></div>
Das war's. Beliebig viele Widgets pro Seite sind möglich. Im WordPress-Backend unter Immo Manager → API & Hilfe → Kapitel 12 gibt es einen Snippet-Generator mit Live-Vorschau, der die Slugs deiner echten Projekte und Immobilien einsetzt.

Attribute lassen sich auch global am <script>-Tag setzen (data-api, data-lang, data-primary, data-accent, data-radius, data-target, data-link-template) und gelten dann für alle Widgets der Seite. Farben kommen sonst automatisch aus den Design-Einstellungen des Immo Managers.

Eigene Detailseiten auf der Kundenseite

Standardmäßig führen „Details ansehen"-Links zur Detailseite der Immo-Manager-Installation. Soll die externe Seite eigene Detailseiten haben, gibst du ein Link-Template mit {slug} bzw. {id} an:

<div data-immo-embed="properties" data-link-template="https://kunde.at/immobilie/{slug}"></div>

<!-- auf https://kunde.at/immobilie/… dann: -->
<div data-immo-embed="property" data-slug="SLUG-AUS-DER-URL"></div>

Für Bauprojekte analog data-project-link-template="https://kunde.at/projekt/{slug}".

Voraussetzungen & Sicherheit

  • CORS: Die Zieldomain muss im Immo Manager unter Einstellungen → API & Integration → Erlaubte Origins erlaubt sein. Standard ist * (alle Domains).
  • HTTPS: Die Immo-Manager-Installation muss per HTTPS erreichbar sein, sonst blockieren Browser das Laden auf HTTPS-Seiten.
  • Nur lesend: Das Widget nutzt ausschließlich öffentliche GET-Endpunkte. Es enthält bewusst kein Anfrage-Formular, weil ein API-Key nie in eine fremde Seite gehört – Anfragen laufen über die Detailseite der Installation.
  • Datenschutz: Keine Cookies, keine Drittanbieter-Ressourcen; Bilder und Daten kommen von der Immo-Manager-Domain. Die Zielseite sollte das Nachladen von Inhalten dieser Domain in ihrer Datenschutzerklärung erwähnen.
  • Content Security Policy: Falls die Zielseite eine CSP nutzt, müssen script-src, connect-src und img-src die Immo-Manager-Domain erlauben.

Fehlersuche

SymptomUrsache & Lösung
Es erscheint gar nichtsDer Editor hat das <script>-Tag entfernt (Text- statt HTML-Block) oder das Script wird nicht geladen. Browser-Konsole (F12) prüfen – [ImmoEmbed] meldet dort jede Ursache.
„Inhalte konnten nicht geladen werden"Meist CORS (Origin nicht erlaubt), ein Security-/Caching-Plugin, das /wp-json blockiert, oder eine falsche API-URL. Test im Browser: API_URL/projects muss JSON liefern. Bei abweichender REST-URL data-api am Script setzen.
Widget abgeschnitten (Wix, Google Sites)HTML-Embeds laufen dort in einem iFrame fester Höhe. Höhe vergrößern oder eine Variante ohne iFrame nutzen (Custom Element / Custom Code).
Dynamisch eingefügte Platzhalter bleiben leerNach dem Einfügen window.ImmoEmbed.init(element) aufrufen; das Script scannt die Seite nur einmal beim Laden.
Farben passen nichtdata-primary, data-accent, data-radius setzen. data-no-shadow="1" rendert ohne Shadow DOM, dann greift das CSS der Zielseite (inklusive ihrer Resets).
Änderungen erscheinen nichtEin Caching-Plugin oder CDN cached die REST-Antworten – Cache leeren bzw. /wp-json vom Cache ausnehmen.
